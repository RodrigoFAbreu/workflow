## 2. Design

### D-Tests (no new test method; each change is an extra assertion, subtest or helper line, and each has a failure-only mutation)

Mutations change the **product** in a scratch copy of the staged fixture only, never in the repository; where the thing hardened is itself a test helper (point 4, m5 and m6) the mutation reverts the helper in the scratch copy, and the plan says so. "Failure-only" means: the original (unstrengthened) **target** test passes under the mutation and the strengthened one fails. It does **not** mean that no other test fails: a mutation of a product line fails every test that already pins that line, and revision 2's claim that no other test of the class fails was wrong for m1, m3, m4 (PTH-E1-001) and m7 (PTH-L3-001). The expected failure set of each mutation is therefore stated below, **measured over the whole of suites I and S** in a stock `stage-conformance` fixture (unmutated: 385 and 1250 tests, all OK), and re-measured the same way at CP1 with the strengthened tests added.

1. **#85 point 1, in I.** In the leftover-takeover test, after the dead takeover guard is planted, also plant the dead claim `PLAN_APPROVAL_JOURNAL.claim.<T>` (the name the takeover uses, next to `ws.plan_approval_journal_path(repo.root)`) **on its own inode**: write the journal's bytes to that name (not `os.link`, which would make the claim the journal's own inode, so that the takeover's clear-and-relink would leave the same inode with the same bytes and nothing could observe it). Record the planted claim's `st_ino` and assert it is not the journal's (`not samefile`) and holds `T`. After the route has run, assert the dead claim was cleared and made again exactly once: the claim exists, its `st_ino` differs from the planted one (the unlink and the single `os.link` onto it happened), it is no longer the live journal (`not samefile`), it still holds the old epoch's `owner_token` (`T`), and the live journal holds the new one. The refusal before the route keeps its existing assertion that the dead guard is untouched (its no-write proof).

### D-Stop

If a strengthened test fails on the unmutated tree, if a mutation fails a test that is not in its expected failure set of D-Tests (or does not fail the strengthened target, or fails its original target), or if any existing test changes its result on the unmutated tree, **stop**: a real defect found by a strengthened test is recorded as a finding in this plan (a separate item) and no code is changed here to make it pass. A requirement that cannot be met without changing behaviour is recorded the same way.
